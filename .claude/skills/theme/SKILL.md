# テーマの地図

テーマを 1 つ受け取り、工程ごとに上場企業を並べた地図を `kessannote/reports/` に置く。地図は
散策の入口で、結論は企業レポートで出す。地図の役目は「どの工程に誰がいて、どこが厚くどこが
薄いか」と「次にどの会社を読むか」を決めること。

先例は 2 本ある。迷ったらこれを開く。

| 地図 | レポート | 横断のスクリプト |
| --- | --- | --- |
| プライベートなナレッジ基盤 | `reports/20260927_private-knowledge-ai-map.md` | `analysis/private-knowledge-ai-map.py` |
| 国産 AI ハードウェア | `reports/20260927_ai-hardware-map.md` | `analysis/ai-hardware-map.py` |

## 前提

| 対象 | 値 |
| --- | --- |
| レポート | `kessannote/reports/YYYYMMDD_<名前>-map.md` |
| 横断のスクリプト | `kessannote/analysis/<名前>-map.py`。レポートと同じ名前 |
| 足切りの SQL | このスキルの `cut.sql` |
| 軸にする未来予測 | `reports/20260927_japan-growth-strategy-2026.md` (日本成長戦略、2026-07-21) |

```bash
cd kabu-app
set -a && . ./.env && set +a
export PGURL="${DATABASE_URL#postgresql+psycopg://}"
```

`DATABASE_URL` にはパスワードが入っている。`echo` しない。

## 手順

### 1. 成長戦略の該当項を読む

成長戦略の本文 (PDF、75 ページ) から、テーマに当たる項目を 2〜3 個探す。出典の URL は
成長戦略の outlook 記事の冒頭にある。1 つのテーマが複数の項目にまたがるのが普通で、
ナレッジ基盤は「バーティカル AI」と「データプラットフォーム」、AI ハードウェアは「半導体」
「クラウド・データセンター」「オール光ネットワーク」に分かれていた。

項目ごとに「何と書いているか」と「数値の目標」を引く。施策の書きぶりからは、国がどの工程を
育てたいのかを読む。AI ハードウェアでは「設計人材の育成」とあり、設計が薄いことの裏返しだった。

ユーザが気にしている筋 (AI ハードウェアでの PFN の MN-Core) があれば、先に聞いて節を立てる。

### 2. 工程に割る

テーマが製品として動くまでを 5〜6 個の工程に割り、表にする。列は「工程」「何をするか」。
割り方の目安は、上流 (モデル・設計・材料) → 本体 → 部品 → つなぐ側 (SIer・基盤) → 使う先。

工程は、有報の語で拾える粒度にする。「データ精製」は AI-OCR や非構造化データで拾えるが、
「価値の創出」は拾えない。

### 3. 有報を横断する

直近の地図のスクリプトを `analysis/<名前>-map.py` に写し、docstring と `KEYWORDS` だけ差し替える。
骨組み (各社の最新の有報、「企業の概況」0101010 と「事業の状況」0102010 の本文、全角の半角寄せ、
並列で読む) はそのまま使う。

```bash
cd kessannote
DATABASE_URL=... KABU_DATA_DIR=/mnt/usb/data python3 analysis/<名前>-map.py > <scratchpad>/<名前>.tsv
```

キーワードの決まりは 3 つ。

- **同じ語を複数の工程に入れない。** 工程の列がそのまま割り当ての手がかりになる
- **大文字小文字を区別する。** 無視すると RAG が GARAGE に当たる
- **英字の略語は前後を英字で囲まれないように書く。** `(?<![A-Za-z])CPO(?![A-Za-z])`。それでも
  広告の CPO や子会社名の NPU が紛れるので、手順 4 で外す

出てくる会社は 300〜500 社になる。工程の数と回数で並べ、上位からおよそ 75〜100 社の文を読む。

### 4. 文を読んで、工程に割る

TSV の上位から、有報の本文で語が出た文を読む。見るのは 3 つ。

- **提供する側か、使う側か。** 自社の業務に RAG を入れた会社は外す
- **製品か、受託か。** 「RAG の構築に対応できる」という開発会社は多い。製品の名前が出ているかで分ける
- **語が別の意味で出ていないか。** 市況の説明に語が出ただけの会社も外す

表の列は「コード」「銘柄」「何を持っているか」「時価総額」「高値比」「営業利益 前期 → 当期」。
「何を持っているか」には、製品の名前と、有報が書いている事業上の位置を 1 行で書く。

主題から外れるが目立つ動き (衣料の会社が GPU サーバーに乗り換えた、など) は、別の小節に
まとめてよい。テーマの熱を示す材料になる。

### 5. 足切りする

候補のコードを `cut.sql` に渡す。

```bash
psql "postgresql://$PGURL" -A -F' | ' -v codes='6526,6834,...' -f ../.claude/skills/theme/cut.sql
```

線は 2 本。先例の 2 本と同じ線を使い、変えるなら理由を書く。

- 高値比が 60% 未満 (直近 250 営業日の高値から 4 割以上下げている)
- 直近の通期が営業赤字、または 2 期続けて最終赤字

高値比の線は [バックテストのまとめ](/reports/20260927_backtest-recap-1/) の「高値から遠い銘柄は
さらに下がる」から来ている。バックテストは順位で測っていて、60% の線そのものは検証していない。
レポートにもそう書く。

表では足切りで落ちた数字を **太字** にし、「足切り」の節に落ちた会社を並べる。営業利益を
開示しない会社 (ソフトバンクグループなど) は空けて、表の下に純利益を書き添える。

### 6. 読みと候補を書く

「読み」は、工程ごとの厚さと薄さ、足切りで何が落ちたかから言えることを、太字の 1 文で始まる
段落で 4〜5 個書く。例: 「日本が厚いのは、チップの周りであってチップそのものではない」。

「次に企業レポートにする候補」は、足切りを通り、工程の中で事業の純度が高い会社から 3 つ選ぶ。
列は「コード」「銘柄」「工程」「選んだ理由」。工程が偏らないようにする。

### 7. 書く

`kessannote/CLAUDE.md` の書き方に従う。frontmatter は次の形。

```yaml
---
title: <テーマ>の地図 — <何をする工程か>
date: YYYY-MM-DD
type: theme
outlook: 20260927_japan-growth-strategy-2026
summary: <テーマに何が要るか>。<成長戦略の目標>。<有報を横断して分かった厚さと薄さ>。<足切りで何が落ちたか>。次に企業レポートにする候補は、A、B、C。
---
```

節の順は、問い → 成長戦略での位置 → 工程 → (ユーザが気にしている筋) → 工程ごとの上場企業 →
足切り → 読み → 次に企業レポートにする候補 → 出し方 → 未確定。

「出し方」には、有報の母集団の数と提出日の範囲、拾った語、1 つでも出た社数、文を読んだ社数と
「読んでいない会社がある」こと、時価総額と高値比の日付と資料、成長戦略から引いた項目の名前を書く。
テーブル名とスクリプトの名前は書かない。

未確定には、少なくとも次を入れる。先例の 2 本とも残っている。

- 大手で語が拾えなかった、または文を読まなかった会社
- 非上場の会社 (提携先としてだけ現れる)
- 工程ごとの売上の規模。テーマの売上をセグメントで分ける会社はほとんど無く、純度は書きぶりで判断している
- 足切りの線を検証していない

### 8. 建てて commit し、push する

```bash
cd kessannote && npx astro build && npx astro check
git add reports/<レポート> analysis/<名前>-map.py && git commit
git push origin main
```

レポートとスクリプトを 1 つのコミットに入れる。ユーザはサイトで読むので、commit したら push する。

## ここからが本番

地図を出すと、ユーザは気になった筋を掘ってくる。AI ハードウェアでは「ラピダスの計画と資金は」
と聞かれ、実施計画と出資者を一次資料で足した。

- **調べた結果は会話で終わらせず、地図に書き戻す。** 筋の節か、工程の表の下に足す
- 外の出来事は、実際に開いた一次資料だけをリンクする。報道しか無ければ「未確定」に落とし、
  「一次資料に当たっていない」と書く
- 候補の企業を読むときは `company` スキルに渡す。企業レポートの frontmatter に
  `theme: <地図のファイル名から .md を除いたもの>` と `outlook: 20260927_japan-growth-strategy-2026`
  を書くと、地図のページに一覧が出る
- 地図は `type: theme` なので上書きしてよい。企業を散策するたびに書き足す

## つまずきどころ

**有報は年 1 回しか出ない。** 2026 年に入って始めた事業は、次の有報まで本文に出てこない。
取りこぼしが疑わしい会社は、短信の本文や適時開示で補う。

**有報は「ＡＩ」「ＲＡＧ」と全角で書く会社が多い。** スクリプトの `text_of` が半角に寄せている。
写すときに消さない。

**上位だけ読むと大手が漏れる。** 大手は語の回数が本文の長さに埋もれ、上位に上がってこない。
ナレッジ基盤では NTT・KDDI・NEC・富士通の国産 LLM を読めずに未確定に落とした。工程に大手が
いるはずなら、社名で当たって文を読む。

**非上場化した会社が地図に紛れる。** 新光電気工業のように、他社の有報に社名だけ残っている。
`stocks` の `is_listed` で確かめる。
